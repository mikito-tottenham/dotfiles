# ADR 0065: git commit は作業単位の完了時に確認なしで実行し、push 以降は承認制のまま残す

## Context

共通ルール（`.chezmoitemplates/agents-common.md`）は 2026-09-09 のユーザー指示により、`git commit` を含む
git / GitHub の状態変更をすべて「操作ごと・セッションごとの明示承認」制にしていた。その結果、Agent は
作業単位が完了し検証を終えても、差分とコミットメッセージ案を提示して停止し、ユーザーの「コミットして」を
待つ往復が毎回発生していた。

2026-09-22、taskell-management の議事録追加作業で Agent がコミットの承認を求めたところ、ユーザーから
「確認しないでもう保存して今後は」と指示があった。コミット（ローカルへの保存）についての確認往復は
価値がなく、以後は不要という判断である。

一方、push・PR 作成・マージ・ブランチ削除・タグ・force push はリモートや共有状態を変える不可逆寄りの
操作で、今回の指示はこれらに言及していない。

## Decision

- `git commit` は、作業単位が完了し検証（テスト・リンクチェック・機密情報の混入確認など）を終えた時点で、
  ユーザーへの確認を挟まずに実行する。2026-09-09 の「コミットも例外にしない」はこの決定で上書きする。
- コミット対象はその作業で意図して変更したファイルに限る。無関係な変更や他セッションの変更
  （同じ作業ツリーに残っている別作業の差分）を巻き込まない。
- 既定ブランチ上で作業している場合は、作業用のローカルブランチを切ってからコミットしてよい
  （ローカルのブランチ作成は確認不要）。
- コミットハッシュ・メッセージ・対象ファイルは作業結果の報告に含め、事後にユーザーが把握できるようにする。
- `git push`・PR 作成・マージ・ブランチ削除・タグ・force push は、引き続き操作ごと・セッションごとの
  明示承認制とする。承認前は差分と PR 本文案の提示までに留める。
- 「保存」の解釈はローカルコミットまでとし、push を含めるかはユーザーの追加指示があるまで広げない。

## Consequences

- 作業完了ごとの確認往復がなくなり、Agent は検証 → コミット → 報告まで一続きで進められる。
- コミットは `git reset` / `git revert` で取り消せるため、誤コミットのリスクはローカルに閉じる。
  リモートへの反映（push）は従来どおり承認が必要なので、共有状態への影響は変わらない。
- 承認を求めない分、コミット前の検証と対象ファイルの限定（`git add` は明示パス指定）が Agent 側の責務になる。
- `dot_claude/CLAUDE.md` の「コミット前に auto memory の内容をプロジェクト CLAUDE.md へ反映するか確認すること」は、
  ユーザーへの確認ではなく Agent 自身の判断として読む（文言は「反映するかを Agent 自身で判断し、反映しない場合は
  理由を作業結果に残す」へ改める）。

## Verification

- `.chezmoitemplates/agents-common.md` の該当行が「commit は確認なし / push 以降は承認制」の 2 項目に分かれていること。
- `chezmoi diff ~/.codex/AGENTS-common.md` が空であること（apply 済み）。
- 次回以降のセッションで、作業完了時に Agent がコミット承認を求めず、報告にコミットハッシュが含まれること。
