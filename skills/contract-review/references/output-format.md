# 出力形式

```markdown
# 契約書レビュー報告 — <相手方名> <契約種類>

- レビュー日: YYYY-MM-DD
- レビューモード: single | multi-2（実行したレビュアー: ...）
- レビュアー: <実行時のモデル ID を列挙。未実行のレビュアーは「未実行」>
- 契約種類: <判定結果>
- 当社の立場: 甲（委託側） | 乙（受託側） | 参考（非当事者）
- 当社側名義: <プロファイルの扱いに従う>
- 契約金額: <有無とレンジ。詳細額は書かない>
- 適用チェック: 共通 + <追加チェック>
- 下請法: 適用あり | なし | 要確認（根拠: 取引類型・資本金区分）

> 本レビューは AI による助言であり、法的助言ではありません。最終判断は <decision_maker> が行ってください。

## エスカレーション警告
（プロファイルの escalation に該当するものだけ）

## 総合評価
| 項目 | 評価 |
|---|---|
| 総合リスク | 高 / 中 / 低 |
| 当社にとっての有利度 | 有利 / 中立 / やや不利 / 不利 / N/A |
| 弁護士レビュー | 推奨 / 不要 |
| 修正交渉 | 必須 / 推奨 / 不要 |

## リスク・懸念事項
### 高リスク
| No. | 条項 | 問題点 | 推奨対応 | 指摘したレビュアー |
### 中リスク
（同じ列）
### 低リスク・参考事項
（同じ列。「法的バックストップあり」の注記はここに書いてよい）

## 評価が分かれた項目（multi のみ）
| 条項 | 各レビュアーの結論 | 採用した結論 | 根拠（position-stances / house_rules） |

## 欠落条項
| No. | 欠落条項 | 重要度 | 追加を推奨する理由 |

## 修正提案サマリー（優先度順）
1. [最優先] ...
2. [優先] ...

## 次のアクション
- [ ] レビュー結果を <decision_maker> に提示
- [ ] （修正交渉する場合）相手方への修正依頼の文案作成
- [ ] 締結時: プロファイルの ledger に従って台帳を更新
```

- single モードでは「指摘したレビュアー」列と「評価が分かれた項目」節を省く
- 相手方への修正依頼メールの文案を作る場合は `japanese-business-writing` を使う。送信はユーザーが行う
