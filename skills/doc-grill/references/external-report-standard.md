# External Report Standard

外部に公開・配布するレポート（旧 `external-report` skill）の規格。doc-grill の pre-send gate で、対象文書が「組織外へ出る数値付きレポート」のときに、この規格への適合を grill とレビューの観点に加える。正本は Markdown 1 ファイル、既定は無記名・中立、すべての数値に出典と基準日を付け、比較の限界を本文で明示した状態でのみ完成とする。

## 出典・数値ルール

- 一次ソース（発行元本体）と準一次ソース（発行元の配信・要約ページ）を優先する。二次記事は一次に到達できない場合の補助に限り、その旨を本文に書く。
- 本文中のすべての数値に `[n]` 形式の出典番号を付ける。段落末にまとめてもよいが、出典のない数値を残さない。
- すべての数値に基準日（as-of）を付ける。表では表内の列か表直下に基準日を書く。
- 推計・補間・按分をしない。値が取れない場合は取れないと書く。目盛りの概読や近似で得た値は **推定** と明記し、以降の節・サマリー・結論で断定表現へ格上げしない。有料壁の内側、非公開、無料公開範囲で検証できなかった項目は **公開データなし** と明記する。
- 母集団・集計方式が異なるデータを別系列の代替値として扱わない。参考として並置する場合は母集団が異なる旨を同じ段落に書く。
- 比較表には基準日・通貨・グロス/ネットなどの費用条件・集計方式（加重方法、中央値/合算）を併記する。条件が揃わない並置表には、行間の直接比較が成立しない旨を表内または表直下に明記し、条件を揃えられないまま優劣を断定しない。
- 出典リストの各項目は、発行元、タイトル、URL、as-of、（あれば）公開日、アクセス日を含む。URL は実在を確認したものだけを載せ、到達できなかった URL は載せず本文側を「公開データなし」に倒す。
- 出典が取れない主張は、書き方を弱めるのではなく落とす。依頼にない予測、推奨アクション、営業的な結論を足さない。

## 名義・免責ルール

- 既定は無記名・中立。組織名・個人名・ブランド・ロゴを入れない。実在の組織や人物の名義を騙る形にしない。
- 案件で名義が必要な場合のみ、免責の直前に名義ブロックを差し込む。名義はユーザーが明示した文言をそのまま使い、Agent 側で作文しない。
- 免責は必ず置き、最低限次を含める: 情報提供であり特定の行為・商品・判断を推奨しないこと／数値の基準日が資料ごとに異なる場合はその一覧／「推定」と明記した箇所とその根拠の弱さ／「公開データなし」の意味（無料公開範囲で検証できなかった）／過去実績が将来を保証しない旨（実績データを扱う場合）。
- 投資・金融、法務、医療・健康、税務、労務など規制領域を扱う場合は、「助言ではない」「判断は読者自身の責任」に相当する記述を免責の先頭に置く。執筆者が有資格者であるかのような表現をしない。
- 機密情報・非公開の社内数値・個人名・顧客実名を正本へ入れない。入れる必要が生じた時点でユーザーへ確認する。

## レビュー観点（7 項目。すべて確認してから公開へ進む）

執筆と数値突合レビューは別ターン・別チェックとして分離し、書いた直後の同一パスで「確認した」と宣言しない。

1. 本文・表・サマリー・結論のすべての数値が、調査 artifact および出典 URL の記載と一致するか
2. すべての数値に出典番号と基準日が付いているか
3. 「推定」「公開データなし」「n/m」などの限定表現が、サマリーや結論で断定へ格上げされていないか
4. 比較表に基準日・通貨・費用条件・集計方式が併記され、条件不揃いの注記があるか
5. 免責が存在し、規制領域なら非助言の記述が先頭にあるか
6. 機密情報・実名・社内限定データが混入していないか
7. 出典リストの各項目に発行元・タイトル・URL・as-of・アクセス日が揃っているか

## 構成テンプレート

Front Matter は `task` / `phase_or_step` / `created_at`（repo 共通の artifact 必須項目）に `title` / `as_of` を加える。節の順序は固定し、2・5・8・9 は削除しない。

```md
---
task: [slug。.context/<date>-<slug>/ と揃える]
phase_or_step: "40-final"
title: [レポート題名。Artifact の title と揃える]
as_of: [レポート全体の基準日 YYYY-MM-DD。系列ごとの基準日は各表に書く]
created_at: [YYYY-MM-DDThh:mm:ss+09:00]
---

# [レポート題名]

[リード 3–5 行。何を対象に、どの範囲の公開情報から、どこまで言えるかを宣言し、免責の節番号を最後に書く]

## 1. エグゼクティブサマリー
[結論先出し 5–7 項目。各項目に数値・基準日・出典番号 [n]。本文の「推定」「公開データなし」と同じ強度で書く]

## 2. [対象 A]  /  ## 3. [対象 B]
[対象ごとに 1 節。数値は表にし、| 期間 / 区分 | 指標 | 基準日 | 条件 | を列に持つ。表直下に 出典：[n] と補足条件]

## 4. [対象間の比較]
[条件を揃えた比較を先に置く。揃わない並置表は「参考」と見出しに付け、
 **この表は基準日・通貨・費用条件が揃っておらず、行間の直接比較は成立しない。** を表直下に書く]

## 5. 方法論上の注意
[指標の性質差／時点・成熟度の差／データ収集バイアス／通貨・為替／集計方式・費用条件]

## 6. [直近環境 / 背景]（任意。数値には出典と基準日）

## 7. 結論
[条件付きで整理。「どちらが優位か」型の問いには成立条件を明示してから答える。含意は推奨アクションではなく「併記すべき条件」の形にする]

## 8. 免責
[名義・免責ルールの必須項目。名義が必要な案件のみ、この直前に名義ブロック]

## 9. 出典リスト
1. **[発行元]**, "[タイトル]", [URL] — as-of: [YYYY-MM-DD]、[公開: YYYY-MM-DD、]アクセス: [YYYY-MM-DD]。
```

## 公開手順の要点

正本は案件リポジトリの配布用ディレクトリまたは `~/Claude/share/<date>-<slug>/<slug>-report.md` に置き、中間成果物は `.context/<date>-<slug>/` に分ける。Claude Artifact は非公開で publish し、共有範囲の設定、SNS 投稿、媒体入稿、メール送付などの実公開操作はユーザーが行う。更新時は同じファイルパスで再 publish して URL を変えず、本文の `as_of` と Front Matter を同時に更新する。
