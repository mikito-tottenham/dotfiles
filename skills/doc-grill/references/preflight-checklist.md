# 送付前検品チェックリスト

社外に出す文書の最終ゲート。収束後、送付・アップロードの前に通し、結果を `.context/<task>/90-preflight.md` に書く。1 項目でも不合格なら「送付可」としない。送付・アップロード・共有設定の変更はこのチェックの範囲外で、ユーザーの明示指示を受けて別に行う。

## 結果の型

```markdown
---
task: <task>
phase_or_step: 90-preflight
created_at: <YYYY-MM-DD>
target: <検品したファイルの path>
source_of_truth: <正本の path と commit / 更新時刻>
---

| # | 項目 | 結果 | 確認方法 | 備考 |
|---|---|---|---|---|
| 1 | ファイル形式 | 合格 / 不合格 / 対象外 | | |

判定: 送付可 / 不可（理由）
```

## 1. ファイル形式

- 依頼された形式（pdf / pptx / docx / xlsx など）で出力されている
- 最新の正本から生成している。正本の更新時刻・commit と派生物の生成時刻を比べる
- ファイル名が repo や組織の規約に沿っている（下書きに付ける接頭辞の要否など）
- 開ける。ページ数・スライド数が想定どおり
- 正本の本文が派生物に欠けずに入っている。派生物をテキスト化（markitdown など）して正本と照合する。見出しと本文が別のテキストボックスに分かれると欠落に見えるので、内容の欠落だけを見る

## 2. 日本語フォント

- PDF: `pdffonts <file>.pdf` で、日本語フォントが埋め込まれている（`emb` が yes）ことと、意図しない代替フォントが無いことを確かめる
- 画像にして目で見る: `pdftoppm -jpeg -r 110 <file>.pdf <outdir>/page` で各ページを画像にし、文字化け（豆腐）、代替フォントへの置き換え、はみ出し、改行位置の崩れを確かめる
- pptx / docx は PDF に書き出してから上の 2 つを行う。macOS で PowerPoint を AppleScript から開くと、ファイルアクセス許可のダイアログで止まることがある。Keynote で開く場合は、Keynote のコンテナ（`~/Library/Containers/com.apple.iWork.Keynote/Data/tmp/`）にコピーしてから開くと書き出せた（2026-09-11 観測）。Keynote の描画は書体・行送りが近似なので、余白に 1 割ほどの余裕を見る
- repo に描画用の script があれば、それを使う

## 3. 顧客に出せない文言

- 内輪の表現、社内の略語、作業者の視点の言い回し（例: 自社を「実験台」と表現する類）
- 保証・断定の表現（必ず、確実に、100% など）で、根拠が無いもの
- 裁定で保留にした論点が、確約の表現になっていないか
- 相手の行為の書き方、敬語の誤り（`japanese-business-writing` で確かめる）
- 相手に伝えた条件・範囲を超える約束
- repo の文言ルールの禁止表現

## 4. 機密・内部メモの混入

- 残ってはいけない作業用の印: `要確認`、`TODO`、`TBD`、`〔`、`［要`、`FIXME`、`xx` などのプレースホルダ
- 内部の path や作業痕跡: `.context/`、`/Users/`、repo 名、branch 名、ADR 番号
- AI の作業メモ: モデル名、エージェント名、「レビュー指摘」「裁定」などの工程の語
- 他の顧客・案件の名称、関係者の実名、金額、連絡先のうち、この相手に出してよいと確認できないもの
- Office ファイルの隠れた情報:
  - pptx: 発表者ノート（`ppt/notesSlides/`）、コメント（`ppt/comments/`、`ppt/commentAuthors.xml`）、非表示スライド
  - docx: 変更履歴（`word/document.xml` の `w:ins` / `w:del`）、コメント（`word/comments.xml`）
  - 共通: 作成者などのプロパティ（`docProps/core.xml`）
  - 確認例: `unzip -l <file>` で該当パーツの有無を見て、`unzip -p <file> <part>` で中身を見る
- PDF のテキスト（`pdftotext`）と Office のテキスト（markitdown など）に対して、上の語を `rg` で検索する

## 5. 送付物一式

- 同時に送る文書（送付メール、質問リスト、案内文）も同じ検品を通した
- 送付メールの本文は `japanese-business-writing` で確かめた
- 添付の数・ファイル名が送付メールの記述と一致している
