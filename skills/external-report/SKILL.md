# External Report

外部に公開・配布するレポートの共通規格。名義を持たない中立フォーマットを既定とし、
すべての数値に出典と基準日を付け、比較の限界を本文で明示した状態でのみ完成とする。

正本は Markdown 1 ファイル。共有は Claude Artifact のリンクで行う。
HTML / PDF / 媒体入稿フォーマットは案件ごとのオプションであり、この規格の必須成果物ではない。

## 成果物契約

- 正本は Markdown 1 ファイル。Front Matter に `task` / `phase_or_step` / `title` / `as_of` / `created_at` を必須キーとして持つ
  (`task` / `phase_or_step` / `created_at` は repo 共通の artifact 必須項目、`title` / `as_of` は本規格の追加分)。
- 正本の保存先は、案件リポジトリの配布用ディレクトリ、または `~/Claude/share/<date>-<slug>/<slug>-report.md`。
- 中間成果物(計画・調査ログ・下書き・レビュー)は `.context/<date>-<slug>/` に置き、正本と混在させない。
- 公開は Claude Artifact への publish。非公開状態で作成し、共有するかどうかはユーザーが決める。
- 機密情報・非公開の社内数値・個人名・顧客実名を正本へ入れない。入れる必要が生じた時点でユーザーへ確認する。

## 構成テンプレート

`references/report-template.md` をコピーして使う。節の順序は固定する。

1. リード(3–5 行): 何を、どの範囲の公開情報で、どこまで言えるかを先に宣言する
2. エグゼクティブサマリー: 結論先出しの箇条書き。各項目に数値と出典番号を含める
3. 本文各節: 対象ごとに 1 節。数値は表にし、表ごとに条件を併記する
4. 比較・方法論上の注意: 指標の性質差、バイアス、時点差など「単純比較が成立しない理由」
5. 直近環境 / 背景(任意): 読み方に影響する外部要因のみ。省略可
6. 結論: 条件付きで整理する。「どちらが優位か」型の問いには、成立条件を明示してから答える
7. 免責
8. 出典リスト

節の追加・削除は可。ただし 2(サマリー)・4(方法論と限界)・7(免責)・8(出典リスト)は削除しない。

## 出典・数値ルール

- 一次ソース(発行元本体)と準一次ソース(発行元の配信・要約ページ)を優先する。二次記事は一次に到達できない場合の補助に限り、その旨を本文に書く。
- 本文中のすべての数値に `[n]` 形式の出典番号を付ける。段落末にまとめてもよいが、出典のない数値を残さない。
- すべての数値に基準日(as-of)を付ける。表では表内の列か表直下に基準日を書く。
- 推計・補間・按分をしない。値が取れない場合は取れないと書く。
  - 目盛りの概読や近似で得た値は本文で **推定** と明記し、以降の節・サマリー・結論で断定表現へ格上げしない。
  - 有料壁の内側、非公開、無料公開範囲で検証できなかった項目は **公開データなし** と明記する。
- 母集団・集計方式が異なるデータを、別系列の代替値として扱わない。参考として並置する場合は母集団が異なる旨を同じ段落に書く。
- 比較表には、基準日・通貨・グロス/ネットなどの費用条件・集計方式(加重方法や中央値/合算)を併記する。
- 条件が揃わない並置表には、行間の直接比較が成立しない旨を表内または表直下に明記する。条件を揃えられないまま優劣を断定しない。
- 出典リストの各項目は、**発行元**、タイトル、URL、as-of、(あれば)公開日、アクセス日を含む。
- URL は実在を確認したものだけを載せる。到達できなかった URL は載せず、本文側を「公開データなし」に倒す。

## 名義・免責ルール

- 既定は無記名・中立。組織名・個人名・ブランド・ロゴを入れない。実在の組織や人物の名義を騙る形にしない。
- 案件で名義が必要な場合のみ、免責の直前に名義ブロックを差し込む。名義はユーザーが明示した文言をそのまま使い、Agent 側で作文しない。
- 免責は必ず置く。最低限、次を含める。
  - 情報提供であり、特定の行為・商品・判断を推奨するものではないこと
  - 数値の基準日が資料ごとに異なる場合はその一覧
  - 「推定」と明記した箇所と、その根拠の弱さ
  - 「公開データなし」とした項目の意味(無料公開範囲で検証できなかった)
  - 過去実績が将来を保証しない旨(実績データを扱う場合)
- 投資・金融、法務、医療・健康、税務、労務など規制領域を扱う場合は、「助言ではない」「判断は読者自身の責任」に相当する記述を免責の先頭に置く。執筆者が有資格者であるかのような表現をしない。

## 制作プロセス

agent-orchestrator と併用する場合は、次の Phase 分担を既定とする。Phase ごとに artifact を `.context/<date>-<slug>/` へ保存し、artifact の生成を次 Phase へ進む条件とする。

| Phase | 内容 | artifact |
|---|---|---|
| 0 | 計画: 観点の上限、出典数の下限、分量上限、完了条件を着手前に確定 | `00-plan.md` |
| 1 | 調査(researcher へ委譲): 出典付きの構造化メモ。生ページ全文を親へ戻さない | `10-research/research.md` |
| 2 | 執筆(writer へ委譲): 本規格の構成テンプレートに沿った Markdown 下書き | `20-draft/` |
| 3 | レビュー(親または別 reviewer。執筆者と分離): 数値突合と限定表現の保持を検証 | `30-review.md` |
| 4 | 公開: 正本確定と Artifact publish | 正本ファイル + URL |

単独で使う場合も、**執筆と数値突合レビューは別ターン・別チェックとして分離する**。書いた直後の同一パスで「確認した」と宣言しない。

Phase 3 のレビュー観点(すべて確認してから公開へ進む):

- 本文・表・サマリー・結論のすべての数値が、調査 artifact および出典 URL の記載と一致するか
- すべての数値に出典番号と基準日が付いているか
- 「推定」「公開データなし」「n/m」などの限定表現が、サマリーや結論で断定へ格上げされていないか
- 比較表に基準日・通貨・費用条件・集計方式が併記され、条件不揃いの注記があるか
- 免責が存在し、規制領域なら非助言の記述が先頭にあるか
- 機密情報・実名・社内限定データが混入していないか
- 出典リストの各項目に発行元・タイトル・URL・as-of・アクセス日が揃っているか

## 公開手順

1. 正本 Markdown を `~/Claude/share/<date>-<slug>/` または案件リポジトリの配布用ディレクトリへ置く。
2. Artifact として publish する。非公開の状態で作成し、`title` は正本の `title` と揃える。
3. 公開 URL と正本のパスをユーザーへ報告する。
4. 共有範囲の設定、SNS 投稿、媒体入稿、メール送付などの実公開操作はユーザーが行う。Agent は実行しない。
5. 更新時は同じファイルパスで再 publish し、URL を変えない。本文の `as_of` と Front Matter を同時に更新する。

## 境界

- この規格は事実の整理と出典提示までを扱う。投資助言・法務助言・医療助言を書かない。
- 出典が取れない主張は、書き方を弱めるのではなく落とす。
- 依頼にない予測、推奨アクション、営業的な結論を足さない。
- レポートの公開・配布・宣伝は行わない。作るのは正本と非公開 Artifact まで。
