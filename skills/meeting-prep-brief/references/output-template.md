# 02-brief.md の書式

```markdown
---
task: <YYYY-MM-DD>-<meeting-slug>
phase_or_step: 02-brief
created_at: <ISO 8601>
---

# <会議名> <YYYY-MM-DD>（<曜日>）<HH:MM> 準備ブリーフ

- 出席者: <氏名（所属）>（カレンダー基準）
- 前回: <YYYY-MM-DD>（出典: <議事録 path または Doc 名>）
- 収集期間: <YYYY-MM-DD> 以降

## 1. 前回の宿題

| 宿題 | 担当 | 判定 | 根拠（日付・発言者・出典） |
|---|---|---|---|
| ... | ... | 進展あり／動きなし／完了 | M/D 氏名 #channel / 件名 |

## 2. この会議で決めること（最大 3 つ）

| # | 決めること | 選択肢 | 推す案と理由（当方の見立て） | 誰が決めるか | 判断に要る材料（出典） |
|---|---|---|---|---|---|
| 1 | ... | A / B | ... | <氏名> | M/D 件名 / #channel / 議事録 path |
| 2 | ... | | | | |
| 3 | ... | | | | |

## 3. 今回の論点

1. <論点>（背景 1 行、出典。どの「決めること」に効くかを書く）
2. ...

## 4. 確認事項

### <相手先 A> への確認
- <質問>（なぜ必要か、出典）

### <相手先 B> への確認
- ...

### 全体での確認
- ...

## 5. ユーザー自身のボール

- <依頼内容>（依頼者、期限、出典）

## 6. 情報源の状態

| 情報源 | 状態 | 備考 |
|---|---|---|
| カレンダー | 確認済み | |
| 過去議事録 | 確認済み | <path> |
| Slack | 確認済み | <channels> |
| Gmail | 確認済み | <件数> |
| Chatwork | 対象外 | 相手先とのルームなし |

## 7. 裏取りできなかった項目

- <項目>（理由）
```

## 書き方

- 「決めること」は、宿題と論点を並べた後に「この会議が終わったとき何が決まっているべきか」を問い直して選ぶ。情報の共有だけで済む項目は論点に残し、ここには入れない。3 つに満たなければ少ない数でよく、無いなら「決めることなし（共有のみ）」と書く。
- 「推す案と理由」は当方の見立てとして書き、出典のある事実と分けて書く。選択肢が 1 つしか無い項目は「決めること」ではなく宿題か確認事項に回す。
- 見出しは会議の進行順に並べる。相手先ブロックは repo の慣習（例: 相手先ごとの 3 ブロック）があればそれに合わせる。
- 推測は「推定」と明記する。出典の無い金額・期限・人名は書かない。
- 共有 Doc に書き込む場合は、Doc 側の書式（見出しレベル・箇条書き）に合わせた別ファイルを作り、書き込み前にユーザーに確認する。
