# brief.md のひな形

`.context/<YYYY-MM-DD>-<meeting-slug>/brief.md` に置き、各サブエージェントに最初に読ませる。

```markdown
---
task: <YYYY-MM-DD>-<meeting-slug>
phase_or_step: 00-brief
created_at: <ISO 8601>
---
# 目的
<YYYY-MM-DD>（<曜日>）<HH:MM> の「<会議名>」（出席: <氏名>）向けに、論点・前回の宿題・確認事項をまとめる。
前回会議は <prev>。ベースラインは <前回議事録 path> の決定事項と宿題。それ以前の項目は扱わない。

# 経路
- 使う経路: <gws-account profile / slack-account profile / コネクタ名>（Phase 0 で接続先を確認済み）
- 他の経路・他アカウントへ切り替えない。失敗したら理由を書いて止める。

# 共通ルール
- 読み取り専用。送信・リアクション・既読化・下書き作成は禁止。
- 出力は指定ファイルに Markdown で書く。親へは「ファイルパス + 3 行以内の要約」だけ返す。
- 各項目に日付（M/D）・発言者・出典（チャンネル名／件名／room 名）を付ける。推測は「推定」と明記する。
- 前回の宿題ごとに「進展あり（内容）／動きなし」を判定し、前回以降の新しい依頼・期限・未回答を列挙する。ユーザー宛ての未対応には ★ を付ける。
- メールアドレスは書かない（氏名で書く）。口座番号・パスワード・token は書かない。
```

# 役割ごとの指示の要点

- Slack: 対象チャンネルとキーワードを渡す。出力 `slack_summary.md`（6KB 以内）: (A) 前回の宿題の進展 (B) 新規事項 (C) 会議で共有すべき動き。
- Gmail: `gmail_meta.json` を渡し、関係スレッドを選ばせて `fetch_threads.py` で本文を取らせる。出力 `gmail_summary.md`（8KB 以内）: (A)(B) に加え、前回会議の自動メモの決定事項とアクション。
- 長い議事録・他会議録: 決定・依頼・期限だけを 5KB 以内に抽出させる。全文は裏取りにだけ使う。

# 親の裏取り

サブエージェントの分類は誤ることがある。金額・承認・期限に関わる ★ 項目は、親が日付を絞った検索で原文を確認してから `02-brief.md` に書く。
